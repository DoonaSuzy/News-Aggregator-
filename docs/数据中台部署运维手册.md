# 数据中台（News Platform）部署与运维手册

> 目标环境：Ubuntu 虚拟机 `192.168.101.84`（用户 `zhu`）
> 架构：FastAPI（核心接口） + Flask（管理后台） + MySQL 8 + Redis，四容器编排
> 数据中台与爬虫 `newsagg` **完全解耦**：独立库 `newsagg_platform`、独立前缀 `PLATFORM_`

---

## 一、架构总览

| 组件 | 容器 | 端口 | 框架 | 职责 |
|------|------|------|------|------|
| 核心接口服务 | `newsagg-fastapi` | 8000 | FastAPI + Uvicorn(Gunicorn) | 文章/来源/省份/统计/鉴权，异步高并发 |
| 管理后台 | `newsagg-flask` | 5000 | Flask + Gunicorn | 来源状态看板、采集概览 |
| 数据库 | `newsagg-mysql` | 3306(内网) | MySQL 8.4 | 独立库 `newsagg_platform` |
| 缓存/限流 | `newsagg-redis` | 6379(内网) | Redis 7 | 缓存与计数 |

- 服务间通过自定义网络 `newsagg-net` 以**服务名**互访（`mysql`/`redis`/`fastapi`）。
- 数据库/缓存**默认不对外暴露端口**，仅 8000/5000 经防火墙开放。
- 依赖顺序由 `depends_on: condition: service_healthy` 保证，MySQL/Redis 健康后才启动应用。

### 分层架构（数据中台）

```
接入层  api/v1/        articles / sources / provinces / auth / health   （FastAPI 路由）
服务层  services/       article_service / source_service / auth_service （业务编排）
数据层  repositories/   article_repo（async SQLAlchemy，repository 模式）
模型层  models/orm.py   SQLAlchemy ORM（独立库表）
横切层  core/           统一响应 / 全局异常 / JWT 鉴权 / slowapi 限流 / request_id 日志
```

## 二、快速部署（三步）

### 前置：本机配置 SSH 免密登录（一次性）

```bash
# 本机生成密钥（如尚无）
ssh-keygen -t ed25519 -C "newsagg-deploy"
# 推送公钥到虚拟机（会提示输入一次 zhu 的密码）
ssh-copy-id -i ~/.ssh/id_rsa.pub zhu@192.168.101.84
# 之后即可免密登录
ssh zhu@192.168.101.84
```

### 步骤 1：虚拟机初始化（安装 Docker 等）

```bash
# 上传仓库到虚拟机（本机执行；或直接在虚拟机 git clone）
rsync -avz --exclude '.venv' --exclude '.env' --exclude 'logs' \
      -e ssh ./ zhu@192.168.101.84:~/News\ Aggregator/

# 登录虚拟机，执行初始化
ssh zhu@192.168.101.84
cd ~/News\ Aggregator
bash deploy/init_vm.sh
# 提示加入 docker 组后，重新登录或执行 newgrp docker
```

### 步骤 2：一键部署

```bash
cd ~/News\ Aggregator
bash deploy/deploy.sh
```

脚本会自动：生成 `.env.platform`（含随机 JWT 密钥与数据库密码）→ 构建镜像 → 启动四容器 → 等待健康 → 打印访问地址。

### 步骤 3：健康检查

```bash
bash deploy/healthcheck.sh 127.0.0.1
```

## 三、访问与验证

| 项目 | 地址 |
|------|------|
| FastAPI 交互文档 (Swagger) | `http://192.168.101.84:8000/docs` |
| FastAPI ReDoc | `http://192.168.101.84:8000/redoc` |

| 健康检查 | `http://192.168.101.84:8000/api/v1/health`、`/health/ready` |

### 接口示例

```bash
# 文章列表（分页 + 过滤）
curl "http://192.168.101.84:8000/api/v1/articles?province=江苏&page=1&page_size=20"

# 文章详情（含正文）
curl "http://192.168.101.84:8000/api/v1/articles/1"

# 省份覆盖
curl "http://192.168.101.84:8000/api/v1/provinces"

# 登录获取令牌
curl -X POST "http://192.168.101.84:8000/api/v1/auth/login" \
     -H "Content-Type: application/json" \
     -d '{"username":"admin","password":"admin123"}'
```

> 开发环境（`PLATFORM_ENV=development`）首次启动会自动播种管理员 `admin / admin123`；生产环境请在建库后自行插入用户并修改密码。

### 统一响应格式

所有接口返回统一信封：

```json
{ "code": 0, "message": "ok", "data": { }, "request_id": "ab12cd34", "timestamp": "2026-10-10T03:00:00+00:00" }
```

错误码语义与 HTTP 状态码一致：`400` 参数错误、`401` 未授权、`404` 不存在、`429` 限流、`500` 服务端错误、`503` 依赖不可用。每个响应都带 `X-Request-ID` 头，便于链路追踪。

## 四、日常运维命令

```bash
cd ~/News\ Aggregator

# 查看状态
docker compose -f newsplatform/docker-compose.yml ps

# 实时日志（可指定服务 fastapi/flask/mysql/redis）
docker compose -f newsplatform/docker-compose.yml logs -f fastapi

# 重启某服务
docker compose -f newsplatform/docker-compose.yml restart fastapi

# 水平扩展 FastAPI 到 3 副本
docker compose -f newsplatform/docker-compose.yml up -d --scale fastapi=3

# 停止并移除容器（保留数据卷）
docker compose -f newsplatform/docker-compose.yml down

# 停止并删除数据卷（慎用，清空数据库）
docker compose -f newsplatform/docker-compose.yml down -v

# 重新构建并更新
docker compose -f newsplatform/docker-compose.yml up -d --build
```

## 五、数据接入（爬虫 → 中台）

数据中台与爬虫解耦，爬虫通过以下任一方式把数据写入 `newsagg_platform`：

1. **接口接入**（推荐）：爬虫调用 `POST` 写入接口或直连中台 MySQL 容器 `newsagg-mysql:3306`。
2. **直连数据库**：从爬虫侧用 PyMySQL 连接 `newsagg-mysql`（库 `newsagg_platform`），按 `sql/platform_schema.sql` 的表结构写入 `sources` / `articles`。

表结构见 `sql/platform_schema.sql`；文章唯一键 `(source_id, url_hash)`，`content_hash` 用于变更检测。

## 六、防火墙与安全

- `init_vm.sh` 默认开放：SSH(22)、FastAPI(8000)、Flask(5000)。
- MySQL(3306)/Redis(6379) **不对外暴露**；如需调试，在虚拟机手动 `sudo ufw allow 3306/tcp` 等，用后关闭。
- **密码不硬编码**：`.env.platform` 由 `deploy.sh` 生成随机值，且已在 `.gitignore` 忽略。
- 生产务必修改：`PLATFORM_JWT_SECRET`（强随机）、数据库密码、默认管理员密码。

## 七、常见问题（FAQ）

| 现象 | 排查 |
|------|------|
| `docker: permission denied` | 未加入 docker 组，`newgrp docker` 或重新登录 |
| FastAPI 反复重启 | `docker compose logs fastapi`；多为连不上 MySQL，确认 `service_healthy` |
| `Bad Gateway` 访问 5000 | Flask 依赖 FastAPI，确认 FastAPI 先就绪 |
| 中文乱码 | MySQL 已设 utf8mb4；检查客户端连接 charset |
| 端口被占用 | 修改 `.env.platform` 的 `FASTAPI_PORT`/`FLASK_PORT` 后重启 |
| 数据丢失 | 误用 `down -v` 删了卷；日常用 `down` 保留卷 |

## 八、本地开发（非容器）

```bash
# 安装依赖（Python 3.11+）
pip install -r newsplatform/requirements.txt

# 离线测试（SQLite 内存库，无需 MySQL/Redis）
pytest newsplatform/tests -q

# 本地起服务（需可达的 MySQL/Redis，或用 database_url_override 指向 sqlite）
uvicorn newsplatform.main:app --reload --port 8000

# Flask 后台
gunicorn -w 2 -b 0.0.0.0:5000 'newsplatform.admin.app:create_app()'
```
