## 二、list_title 链路（本次交接的起点）

已确认并打通：

1. **Schema**：`article_tasks.list_title VARCHAR(512) NULL`（线上 `ALTER TABLE` 已执行，`sql/schema.sql` 已同步）。
2. **`repo.upsert_discovered`**：新增 `list_title` 入参；`INSERT IGNORE` 命中已存在行时，
   若库内 `list_title` 为空则用新值回填 —— 历史候选行也能被后续轮次修复。
   首次插入才返回 `True`（决定是否发详情请求），语义不变。
3. **`session.CrawlSession.consider(..., list_title=)`**：缓存到 `self._list_titles[url_hash]`
   并透传给 repo；`list_title_for(url_hash)` 供详情落库兜底。
4. **`spider.parse_list`**：`session.consider(item.url, nh, list_title=item.title)` 已传列表标题。
5. **`spider._store`**：`title = clean_title(detail.title) or clean_title(session.list_title_for(nh))`
   —— 详情页标题缺失时回退列表页标题。

## 三、18 个来源零产出的真实根因（不是解析问题）

逐一实测栏目页后定位到三处基础设施问题，逐个修复：

### 1. 关闭重定向 → 18 个栏目页空跑（最主要坑）

`crawl/settings.py` 原先 `REDIRECT_ENABLED = False`。而省级栏目页普遍是
`http → https` 的 301/302（红网、南方网、大众网、河北新闻网、大河网…共 18 个）。
不跟随重定向时，列表回调收到 3xx，被 `HttpErrorMiddleware` **静默丢弃**，
表现为 `discovered=0 finished`，任务"成功"但一条都没抓到。

修复：`REDIRECT_ENABLED=True` + `REDIRECT_MAX_TIMES=5`；
同时把 17 个来源的 `column_url` 直接改成 https 终址（少一跳，也避免自跳循环）。

### 2. 关闭 Cookie → 南海网 302 自跳

南海网用一次性 Cookie `C3VK` 做反爬校验，不带 Cookie 会无限 302 到自己。
修复：`COOKIES_ENABLED=True`（站点无登录态，无隐私影响）。

### 3. `is_article` 过严 + 子域不放行 → 11 个来源候选数为 0

- `_ARTICLE_HINT` 只认 `content_\d+` / `/YYYY-MM-DD/` 等少数形态，实测覆盖不到
  `/\d{5,}\.s?html?$`（辽宁/陕西/每日甘肃/四川/江西）、`/t\d{6,}\.htm`（长江网）、
  `system/\d{8}`（四川）、`/node_xxx/yyy.shtml`（南方网）、`/content/<uuid>.html`（劳动报/金湾）。
- `_SKIP_HINT` 里的 `/node_` 误杀南方网详情；已改为"以节点段结尾"才排除。
- 正文常分布在 `news./china./hn./moment./liaoning.` 等子域，而 `allowed_hosts` 只写了
  `www.x.y`。`allows()` 现在会从 `www.x.y` 派生父域 `x.y` 放行子域。

**修复后各来源候选数**：湖南 0→241、广东 0→176、辽宁 0→188、吉林 0→96、
重庆 0→137、四川 0→90、西藏 0→73、陕西 0→75、甘肃日报 0→89、河南 0→187、长江 0→18。
其余来源无回归（已跑全量诊断确认）。

## 四、正文提取兜底

原 `_extract_paragraphs` 只认 21 个常见容器选择器，云南网、辽宁东北新闻网、
湖北荆楚网、华龙网、西藏新闻网、广西广电等站点一律落空（空正文 2005 篇）。

新增**全文 `<p>` 密度兜底**：容器选择器都没命中时，扫描全文 `<p>`，按
长度 ≥15、链接文字占比 ≤60%、页脚关键词（版权/ICP/责任编辑/来源：）过滤，
总量 ≥120 字才认作正文。云南/辽宁/湖北/重庆/西藏等来源正文一次性救回。

来源名同理加了兜底：选择器没命中时全文扫 `来源：xxx`（山东"大众新闻"、
湖南"益阳日报"、重庆"第1眼TV-华龙网"均命中），无来源从 3349 降到 839。

## 八、新增运维脚本（`scripts/`）

| 脚本 | 用途 |
| --- | --- |
| `diagnose_sources.py` | 全量/指定来源诊断：HTTP 状态、`<a>` 数、`is_article` 命中、`parse_list` 产出 |
| `dump_links.py <adapter>` | 导出栏目页链接形态（host 分布 + 疑似文章链接） |
| `probe_detail.py <adapter> <url>` | 单页解析质量（标题/来源/时间/段落） |
| `run_batch.py [--days N] [--sources …]` | 绕过槽位手工建批并投递 |
| `sync_sources.py [--apply]` | 适配器 `column_url` → `sources` 表 |
| `repair_titles.py [--adapter X] [--limit N] [--dry-run]` | 空标题/空正文定向修复 |
| `quality_report.py [--top N]` | 逐来源质量报表 |
| `debug_crawl.py <adapter>` | DEBUG 日志跑单任务，定位空跑 |

常用命令：

```bash
# 全量建批并投递（8 worker 已在跑的前提下）
python scripts/run_batch.py --days 30

# 起 worker（修复模式重抓补元数据）
NEWSAGG_WORKER_COUNT=8 NEWSAGG_REFRESH=1 python -m newsagg supervisor

# 质量体检
python scripts/quality_report.py --top 10
```
