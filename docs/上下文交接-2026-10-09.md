### 3. 关键决策与方案取舍

| 决策 | 结论 | 理由 |
|---|---|---|
| 重定向 | 开启 `REDIRECT_ENABLED=True`（最多 5 跳） | 18 个栏目页是 http→https 的 301/302，关闭会让列表回调收到 3xx 被静默丢弃，任务 `discovered=0` 空跑 |
| Cookie | 开启 `COOKIES_ENABLED=True` | 南海网用一次性 `C3VK` Cookie 反爬，关 Cookie 会 302 自跳死循环 |
| TLS 降级 | 仅江西按 `tls_ciphers="DEFAULT:@SECLEVEL=1"` 在**该来源任务进程**内下发，其余来源保持默认 | Scrapy 仅支持全局 `DOWNLOADER_CLIENT_TLS_CIPHERS`，不支持每请求设置；全局降级会拖累所有来源安全性 |
| 渲染方案 | 渲染修复放在独立脚本而非爬虫中间件 | Playwright 同步 API 的 greenlet **不能跨线程**，Scrapy 在 Twisted 反应器内跑渲染极易崩溃；改为脚本两阶段（并发静态 + 主线程串行渲染） |
| 空正文判定 | 区分"真无正文"与"视频稿" | 广西(gxtv)、青海(qinghai)、南海网部分稿件正文区只有 `<video>`，空正文属正常，不应算作解析失败 |
| URL 日期兜底 | 当页面无时间字样时从 URL 抽日期 | 浙江在线专题页（`t20220329_`）等 URL 自带日期 |

### E. 易错点与陷阱（务必先看）

- **不要在 worktree 目录改代码** —— 必须在 `D:/project/News Aggregator`。
- **Redis 端口 6380**，不是 6379。
- **Scrapy 每任务独享进程**：改 spider/settings 必须重跑 `run_batch.py` + supervisor 才生效；之前用 `crawl-once --refresh` 也行。
- **Playwright 不能跨线程**：渲染逻辑一律放在 `render_harvest.py`/`repair_titles.py` 的**主线程串行阶段**，绝不要塞进 `ThreadPoolExecutor`。
- **`repair_titles.py` 的 `--render` 阶段**内部已自动串行，但 `--workers` 只影响第一阶段（静态）并发。
- **空正文≠失败**：gxtv/qinghai/hainan 有纯视频稿，属预期，别为了"清零空正文"去误改解析器。
- **Worker 曾因 Redis `Timeout reading from socket`（869 次）反复崩溃**，已在 `worker.run_worker` 用 try/except + 重连修复；若又见 worker 频繁退出，优先查 Redis 连接而非爬虫。
- **诊断脚本** `diagnose_sources.py` 的 `fetch()` 默认把无 header charset 的页面当 utf-8 解码，会**伪造** GBK 站（如青海）的乱码；真实爬虫走 Scrapy 的 `meta http-equiv` 解码是正常的。看诊断输出时需心里有数。
